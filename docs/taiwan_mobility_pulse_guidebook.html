第一章：數據哲學與選型抉擇——為什麼是「剛性骨架＋彈性肌肉」？

「在資料科學的世界裡，海量不等於精確。若基礎座標在漂移、身分全靠猜測，再複雜的神經網路也只是在放大幻覺。」

1.1 交通大數據的永恆難題：雜訊與推估的代價

在過去十年間，智慧交通與人流分析最常遭遇的挫敗，就是「對單一資料源的過度迷信」。 許多專案試圖單純依賴「手機電信信令（Cellular Signaling Data）」來解決所有的都市問題：從捷運客流、路網壅塞到商圈消費。然而，當專案進入審計、驗收或精細規劃時，往往浮現巨大的落差：

  • 為什麼捷運地下三樓月台的人，會被信令判定在上方的高架橋上開車？
  • 為什麼信令推估出的人次，無法拿來發放政府百億元的 TPASS 預算補貼？
  • 為什麼使用者連續停留了 8 小時，我們卻不知道他是上班族、學生還是外籍遊客？

交通大數據的真正挑戰，從來不是「數據量夠不夠大」，而是資料工程的本質屬性。 本專案在立項之初，便確立了核心的資料哲學：「以零漂移的物理剛性真理作為骨架，以全域連續空間作為肌肉」。

1.2 為什麼選擇 TICP 交通票證大數據？（公分級剛性真理）

我們選用了交通部 TICP（運輸資料流通服務平臺）高達 4.48 億筆 的真實票證大數據，作為本研究的核心公共運輸基石。它的不可替代性體現在三個「絕對維度」：

  1. 100% 物理全量普查（Census，非抽樣擴推）： 每一次刷卡進出站，都是一筆帶有金融交易憑證的實體紀錄。沒有所謂「市佔率乘上 2.7 倍」的統計抽樣擴推偏差，數據就是真實的物理客流。

  2. 法律契約與法定票種（Ground Truth Persona）： 每筆票證紀錄自帶法定身分標籤：

  3. TicketType=4：TPASS 通勤月票（政策受惠的重度通勤剛需族）。

  4. TicketType=03/04：敬老愛心卡（65+ 長者或身障族群，享有地方政府法定補貼）。
  5. TicketType=02：學生卡（國高中大專學生，尖峰接送與通學模式）。

  6. Token / QR 單程票：境外觀光客或偶發搭乘者。 身分是「客觀法律事實」，完全無需演算法通靈猜測。

  7. 公分級月台與垂直高度定位（Z 軸精度）： 閘門精確架設在地下二樓、地下三樓或高架月台。無論地面遮蔽如何嚴重，刷卡進站即 100% 確立該人次身處軌道系統內部，徹底杜絕高程混淆。

1.3 為什麼選擇 eTag 高速公路車流？（0m 門架客貨分流）

在公路運輸與城際走廊領域，我們納入了高速公路局 eTag 百萬級車流大數據：

  1. 0m 樁號精準度，絕對零空間漂移（Zero Drift）： eTag 微波感應門架固定架設在國道精確的公里樁號（如國道一號 23.4k）。車輛通過即紀錄，座標固定不變，資料清洗只需做時間格式檢查，無需耗費算力做路網投影。

  2. 監理車籍 5 大車種分類（客貨分離的生命線）： eTag 系統依據車籍與車軸數，將車流精準拆解為：

  3. 車種 31：小客車（私家通勤、家庭旅遊）。

  4. 車種 32：小貨車（都會短途配送、工班車輛）。
  5. 車種 41：大客車（國道客運、觀光遊覽車）。
  6. 車種 42：大貨車（城際幹線重型物流）。

  7. 車種 51/52：聯結車／半聯結車（國際商港貨櫃、鋼鐵重工業）。 這使我們能夠看見台灣真實的「產業物流骨骼」，這是任何公共運輸票證無法觸及的領域。

  8. 與票證具備「天然精準互斥性（Mutual Exclusivity）」： 一個人同一秒鐘，絕不可能「既在國道上自駕，又在捷運車廂刷卡」！因此： $$\text{總城際走廊流量 } Q_{\text{Total}} = Q_{\text{eTag (公路汽客貨)}} + Q_{\text{Ticket (軌道/客運)}}$$ 兩者可直接相加，零重複計數，是計算全台「運具分擔率（Modal Split）」最純淨的黃金組合。

1.4 為什麼結合 TDX 停車與生活圈機能？

車輛從高速公路下匝道後，並不會憑空消失。 車流注入周邊平面市區後，首當其衝的就是「停車空間承載力」與「生活圈零售機能」。 因此，我們將 TDX 即時停車位 API、生活機能設施密度（充電樁、超商、量販店）與交流道下匝道車流進行深度關聯，讓宏觀的高速公路車流能夠無縫落地為微觀的「生活圈都市承載力指標」。

1.5 電信信令的局限：空間漂移、UID 洗亂與車廂重複計算

手機電信信令（Cellular Signaling）在全域覆蓋上極具價值，但在交通資料工程中存在三大致命痛點：

  1. 空間漂移與乒乓交遞（Ping-pong Handover）： 基地台半徑在市區約 200~500m。當使用者靜止不動時，手機頻繁切換鄰近基站，演算法極易誤判為高速移動；當遇到高架橋與地下捷運時，更是分不清人在哪一層。

  2. 去識別化洗亂導致旅次鏈斷裂： 為遵守《個人資料保護法》，電信業者的臨時 ID（IMSI/UID）通常每天或每週重新 Hash 洗亂，並在空間網格中注入微擾噪音。一旦 UID 被洗亂，就無法進行跨週跨月的連續旅次鏈追蹤，分不清常客與偶發過客。

  3. 車廂雙重計數（Double-Counting）： 當乘客搭捷運時，信令基站偵測到手機並擴推 2.6 倍，捷運閘門又記錄 1 次。若直接將信令與票證相加，捷運車廂的人潮會被嚴重虛胖放大！若要扣除重複，因缺乏明文個資，只能用機率猜測，再次引入二次估計誤差。

2.5 數據前處理工程挑戰與安全保護 (Data Pipeline Nuances)

國家級交通大數據前處理安全防護管線
▼ 雙軌平行架構 ▼
個人隱私加鹽去識別化
Independent Salt Hash Architecture
  • 各營運商採用獨立 Salt，禁止跨商串接個人私密行蹤軌跡
  • 跨運具轉乘完全依賴票卡晶片「實體寫入代碼」嚴格判定
記憶體零爆破串流架構
PyArrow Streaming Pipeline
  • 16MB 區塊串流解壓縮，全管線不落磁碟避免 I/O 瓶頸
  • Polars LazyFrame 欄位下推投影，安全控制在 1.5GB RAM 水位
▼ 終端產物 ▼
最終成果：16.5GB 高壓縮 Apache Parquet 剛性母體 (體積精簡 88%)
  1. 獨立加鹽雜湊機制（Independent Salting Hash）：
  2. 為貫徹個人隱私防護，TICP 規範要求各營運商（公車、捷運、台鐵、微笑單車）對悠遊卡/一卡通卡號採用獨立加鹽雜湊（Unique Salting Algorithm）。
  3. 因此，工程上無法單純利用卡號欄位跨系統直接串聯同一人的所有行蹤；
  4. 然而，跨運具之轉乘關係是由實體驗票機晶片直接讀寫寫入公車端的 TransferCode 與 Discount（記錄 100% 精準法律核銷憑證）；而公共自行車則透過站點空間拓撲與分時潮汐特徵實現宏觀整合。
  5. 記憶體零爆破安全串流管線（Memory-Safe Streaming Pipeline）：

5.3 風雨中的行為巨變：天候模擬實驗室

7.3 專利級數據工程思維：硬錨點反向校正技術 (Ground Truth Anchoring)

反向校正三大核心機制：

  1. 擴推倍率動態修正（Expansion Factor Tuning）： 電信業者傳統上按照全台平均市佔率（如 38%）乘以固定的 2.63 倍。然而，在特定站點（如外籍移工高密度的中壢站、高鐵商務客密度的竹北站），電信市佔率存在嚴重偏誤。透過將車站票證總量作為分母，系統能動態反算該時空網格的真實電信採樣倍率，消除擴推偏差。

  2. 路徑吸附校驗（Map Matching Ground Truth）： 當信令在高架國道一號與地下中和新蘆線之間猶豫不決時，若同時間頂溪站有刷卡紀錄，系統自動將信令權重 100% 吸附至地下軌道網絡，瞬間消除路徑幻覺。

  3. 隱私計算與時空微碰撞（Privacy-Preserving Co-occurrence）： 完全無需交換個人姓名、身分證字號或手機號碼。在特徵層採用聯邦學習（Federated Learning）架構，僅對齊「時間（分鐘級）」與「空間門架/閘門坐標」，在合規隱私紅線內達成最高精度的行為合成。
